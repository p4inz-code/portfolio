# Audit: feat/showcase-themes (2026-09-21)

Scope: everything on the branch since v5.24.1 (main is untouched). Preview build served locally,
Chrome only. Not tested: real iOS Safari, real Android devices, Firefox (see "Not verified").

## What changed on the branch

- **Scroll engine** (`src/scripts/progress.ts`): a JS driver that gives the pinned-chapter choreography to
  phones, Firefox and iOS without scroll timelines. Sets `--p` per element and `--sp` for the page.
  Desktop with native timelines is unchanged.
- **Home**: scrubbed hero (words light up as you scroll, a row of ghost team members collapses into one),
  pinned chapters now also run on phones as stacked cards with per-scene effects.
- **/work**: no longer the same showcase. A deck of sticky cards that stack and shrink, plus a full roster index
  with hover previews.
- **Scenes** on all five case studies (Nexus, Kanvaz, Ascent, Mission OS, Pursue OS) with extra layers:
  dial and hex streams, collaborator cursors, orbs + pixel runner + level HUD, dusk lake + boot log + privacy
  radar, investigation graph + tracing lens. Stats count up or decrypt on entry.
- **Ascent stars in light theme**: visible now (ink stars and streaks on the lavender sky).
- **Contact**: magnet removed. Added live Navi Mumbai time with offset from the visitor, five-bar signal meter,
  quick-start chips, copy-email, and a transmit beat before the mail client opens.
- **Page transitions** (cross-document view transitions), nav drawer moved to 900px.
- **Motion control** (WCAG 2.2.2): pause/resume ambient motion in the header and drawer, remembered.

## Accessibility (WCAG 2.1 AA)

Fixed:
- Home hero words were dimmed with opacity (contrast 1.3-1.4:1). Now they go from `--muted` (7:1) to `--text`;
  `prefers-contrast: more` shows the finished sentence.
- Autoplaying gameplay loop and moving backdrops had no pause (2.2.2). Added the motion toggle; the loops stop too.
- Nameless button (the live-stats pill on phones hid its text with display:none). Now visually hidden.
- Label-in-name mismatch on the deck links. The accessible name now starts with the visible text.
- Unnamed `aside` landmarks removed. Contact send button gradient kept above 4.5:1.
- Decorative layers are `aria-hidden`; animated stat values keep the real value in a hidden span.

Token contrast (dark / light): text 15.4 / 15.7, muted 7.0 / 8.0, muted-2 5.6 / 6.0, purple-bright 12.2 / 6.7 on `--bg`.

Remaining or by design: text in a not-yet-lit state exists during the hero scrub (now muted, above AA); the
`Transition was skipped` AbortError is logged by the browser when a view transition is skipped (hidden tab).
Touch targets on coarse pointers are 40-44px for the new controls; some older components are 34px.

## Awwwards-style rating (my estimate, not a jury)

Awwwards weights: Design 40%, Usability 30%, Creativity 20%, Content 10%; 6.5 average earns Honorable Mention; SOTD
thresholds are not published.

| Criterion | Score | Why |
|---|---|---|
| Design (40%) | 7.0 | Cohesive art direction, each project has its own world, restraint in light theme. Held back by typography: the base fonts never load (Neue Machina/Montreal/Supply Mono are not on Fontshare), so display type is Helvetica/Arial. Mission OS and Pursue OS have no real media. |
| Usability (30%) | 7.4 | Accessibility 100 on tested pages, performance 92-100, clean responsive matrix, pause control, reduced motion, everything reversible. Costs: very long scroll on home, no preloader/orientation. |
| Creativity (20%) | 7.6 | Scrubbed hero pun, moon phase, runner and level HUD, investigation lens, deck vs pinned chapters, outline-to-fill titles. No WebGL, no custom cursor, no sound. |
| Content (10%) | 7.0 | Honest and specific copy, real repos and versions. Thin case studies for two products. |

**Weighted: 7.2.** Plausibly Honorable Mention territory; SOTD would need the typography fixed and more real media.

Biggest levers, in order: 1) real display typography; 2) real screenshots or recordings for Mission OS and Pursue OS;
3) a short intro/preloader that sets the scene; 4) a custom cursor that reacts per scene; 5) a real-device pass on iOS
Safari and Android Chrome.

## Code review (skill, medium)

Reviewed `main..HEAD` by hand. Fixed: scroll engine read and wrote layout in an interleaved loop (forced a layout per element per frame); Ctrl/Cmd+Enter could submit the contact form a second time during the transmit beat; the level HUD counter relied on a non-integer `calc()` for an integer property (now `round()`).

## Not verified

iOS Safari, real phones (only Chrome emulation and iframe widths), Firefox (falls back to the JS engine, never run),
autoplay in a foreground tab, view transitions visually (only that navigation works), reduced motion by emulation
(gated by media queries, not toggled in devtools), screen readers.
